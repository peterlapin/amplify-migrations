# Example: [Amplify Gen 2][amplify-gen2] + amplify-migrations

[amplify-gen2]: https://docs.amplify.aws/react/build-a-backend/

Minimal end-to-end example that deploys a Todo model and runs a seed/backfill migration on every `ampx sandbox` push.

## Prerequisites

- Node >= 22
- An AWS profile with permissions to run `ampx sandbox` (creates Cognito, AppSync, DynamoDB, Lambda)
- `pnpm install` at the repo root

## Run it

From this folder:

```bash
# 1. Build the workspace packages that the example depends on
pnpm -w build

# 2. Launch an isolated Amplify sandbox (creates real AWS resources in your account)
pnpm sandbox
```

On first deploy, CloudFormation provisions:

- Cognito user pool (from `auth/resource.ts`)
- AppSync + DynamoDB `Todo` table (from `data/resource.ts`)
- A nested `AmplifyMigrations` stack containing the private state table + runner Lambda
- A `CustomResource` that invokes the runner Lambda

The runner Lambda executes `Migration20260415120000-seed-todos.ts` automatically. Check CloudWatch Logs under `/aws/lambda/<stack>-RunnerFn-*` to see the per-migration output.

## Verify the migration ran

```bash
# amplify_outputs.json is generated by ampx; the CLI finds the state table via the
# `custom.amplifyMigrations` entry we add to it.
pnpm migrations list
pnpm migrations pending
```

## Create another migration

```bash
pnpm migrations create add-archived-field
# edit the generated file, then:
pnpm sandbox        # redeploys; the runner picks up the new file
```

## Tear down

```bash
pnpm sandbox:delete
```

Because the example sets `stateTableRemovalPolicy: DESTROY`, the migration state table is removed with the stack. In production you'd leave it at the default `RETAIN`.
